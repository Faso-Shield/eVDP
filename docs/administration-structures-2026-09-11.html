Coordinateur national

Création du compte de l'agent DSI

Ici, la plateforme montre sa limite connue : il n'existe aucun formulaire dans l'application pour créer un compte de staff interne (Triager, Analyste, ou agent DSI). Seule l'auto-inscription publique (réservée aux rôles chercheur) passe par un formulaire web. La création de ce compte s'est donc faite par la voie technique de secours.

shell — manage.py shell
>>> User.objects.create_user(
    email='dsi.mshp@sante.gov.bf',
    full_name='Adama Kabore',
    role=Role.DSI_ADMIN,
    email_verified=True,
  )
<User: dsi.mshp@sante.gov.bf>
Constat produit : c'est le vrai écart identifié dans l'audit de cette session — onboarder un nouvel agent CSIRT ou DSI nécessite aujourd'hui un accès technique (admin Django ou shell), pas un simple formulaire. Pas bloquant pour une petite équipe, mais à garder en tête pour un passage à l'échelle.

Ce que cette session démontre

  • Structure ↔ agent ↔ programme sont trois objets distincts, liés explicitement — jamais de couplage implicite.
  • Multi-appartenance : un même compte peut être membre de plusieurs organisations (le modèle OrganizationMember le permet nativement).
  • Aucun montant codé en dur : toute la matrice de récompenses est une donnée de configuration, modifiable sans toucher au code.
  • Un vrai écart produit confirmé en le vivant : la création de comptes internes reste un geste technique, pas un parcours utilisateur — point d'attention pour la suite du projet.
